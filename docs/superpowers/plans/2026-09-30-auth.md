# Phase 2 Authentication Implementation Plan

**Goal:** 在既有工程实现用户模型、JWT认证与三角色前后端登录闭环。
**Architecture:** 复用统一响应和分层；Spring Security + JOSE 校验JWT，数据库用户状态与版本决定有效性；Pinia、Axios、Router协作。
**Tech Stack:** Java17 / Boot3.5 / MyBatis Plus / MySQL8 / BCrypt / Vue3 / TypeScript。
**Spec:** docs/superpowers/specs/2026-09-30-auth-design.md
**Execution:** 本会话直接执行；用户已明确授权完成本阶段，保持最小依赖且禁止GUI。

## 全局约束
不实现报修/维修/派单/地图/统计；不重排目录、不损坏Phase1；不全局安装工具。

## 任务
- [x] 认证安全：先写匿名路由与登录HTTP失败断言；新增JOSE/Security必需依赖、JwtProperties/JwtUtils/TokenFilter/UserAuthenticationService/SecurityConfig；测试签名、过期、issuer、配置缺失。
- [x] 用户与数据库：新增UserEntity/UserMapper/UserService/LoginRequest/UserVO/AuthVO/UserController/AuthController；SQL建表与单独开发账号脚本，幂等且不覆盖已有密码/状态；真实数据库登录/禁用/3×3授权/退出撤销验证。
- [x] 前端闭环：先写匿名路由失败断言；新增auth API/Pinia/store持久化工具，修改Axios、路由守卫、登录页、共享Layout、首页；测三角色登录与刷新恢复、401、角色隔离、退出。
- [x] 界面：复用组件与系统字体；Apple风格浅色视觉，响应式、焦点反馈、轻微动画与reduced-motion；SSR无警告、Vite模块可访问。
- [x] 验证与报告：Maven verify、前端类型构建和状态/SSR检查、真实HTTP权限矩阵、只读安全评审；更新README与Phase2验证记录。

## 评审重点
- token签名、exp/issuer/版本必验，不信任客户端角色。
- 禁用/删除账号与退出旧token立即失效；数据库失败不可授权。
- 密码/密钥不进入响应、日志或提交文件。
- 刷新、并发恢复、401与登录失败不能产生错误角色跳转。
- SQL重复执行不覆盖现有用户；移动端导航和reduce-motion可用。
