# Phase 3 核心报修闭环设计

沿用 Phase 1/2 的 Java 17、Spring Boot、MyBatis Plus、JWT、Spring Security、Result/PageResult、Vue3/Pinia/Router/Axios。无新增依赖，无 GUI 自动化，不更改认证算法或角色边界。

## 业务规则
- 学生、维修员使用 user_id 唯一关联的 student/worker 档案；开发 SQL 补齐现有测试账号档案。楼栋与故障类型幂等初始化。
- 提交直接产生 WAIT_AUDIT；CREATED 保留枚举，当前无草稿接口。
- WAIT_AUDIT → 管理员审核 → WAIT_ASSIGN。人工分配接口指定启用维修员，状态保持 WAIT_ASSIGN；指定维修员接单 → ASSIGNED → 开始 PROCESSING → 有维修记录才能完成 WAIT_CONFIRM → 订单所属学生确认 FINISHED → 一次评价 COMMENTED。
- 所有状态转换在事务内锁定订单行，后端指定目标状态，不接受通用状态修改。评价唯一约束防重复；完成数与评分同步在事务内维护。
- 学生仅自己订单、维修员仅已分配自己的订单、管理员所有订单。详情与图片执行相同归属校验。未知/非参与者订单返回404，不泄漏订单存在性。
- 订单事件保留提交/审核/指定维修员/接单/开始/完成/确认/评价的真实时间，供时间线使用。
- 上传学生/维修员本人图片：PNG/JPEG，5MiB上限，20百万像素上限，校验实际格式并重新编码，UUID文件名。图片元数据记录所有者和绑定订单；提交只接受本人未绑定上传地址。下载必须认证且是所有者或绑定订单参与者，不公开目录。
- 工单筛选分页上限100，状态/类型/起止日期；维修工作台和学生首页计数仅为基本业务数量，无分析 Dashboard。

## 前端
浅色系统字体、蓝色强调、圆角和留白，沿用现有 Layout 和登录页。共用 OrderCard、OrderTimeline、ProtectedImage、ImageUpload。学生首页/我的报修/五步报修向导/详情；维修首页/任务卡片/详情维修记录；管理员工单筛选、详情审核及人工指定维修员。按钮防重复、失败显示、成功反馈、空状态、加载状态、减少动画、移动端布局。

## 验证
旧认证测试回归、状态测试、图片测试、真实 MySQL+HTTP 多角色闭环/越权/重复操作/并发操作/上传拒绝和读取权限；前端 TypeScript+构建、真实 Axios API 闭环、SSR页面渲染。不使用浏览器或GUI自动化，视觉和真实浏览器控制台验收边界明确报告。

## 范围
不实现智能派单、地图、分析Dashboard、工单聊天；不新增注册/账号管理/重置密码。保留Phase4需求。
