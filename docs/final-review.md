日期：2026-09-30。以当前源码和数据库为依据，保留之前未提交的流程增强与通知事务解耦代码。未新增业务、依赖或数据库迁移，未改JWT、角色模型、订单状态机、派单算法或地图逻辑。

## 发现与实际修复

| 问题 | 修复 |
| --- | --- |
| 维修员被重派后仍可读取自己上传的已绑定图片 | 已绑定图片统一检查当前工单归属；未绑定图片仍仅上传者可预览 |
| 登录异步校验期间快速点击会发送两次登录请求 | 校验前锁定提交，校验与请求共用finally释放Loading |
| 重派后刷新聊天会将旧草稿发给新维修员 | 草稿记录原接收人，接收人变化时保留草稿并要求确认后再次发送；继续传expectedWorkerId给后端 |
| 图片接口的JSON权限错误被Blob响应类型掩盖 | 解析Blob错误正文，区分401、403、404、超时与连接失败，保留原会话防竞态检查 |
| 无负责人的WAIT_ASSIGN显示“待接单” | 共用状态文案根据workerId区分“待派单”和“待接单”；状态枚举不变 |
| 重提标题上限100与创建/后端120不一致 | 统一为120 |
| 详情归属校验重复查询学生/维修员档案 | 单次查询后比较订单归属，保持原404与账号可用性检查 |
| 首页与驾驶舱重复COUNT/档案查询 | 条件聚合替代重复扫描，保留原统计口径及维修员今日派单查询 |
| 折叠导航长文案溢出、详情页导航没有选中 | 紧凑文案及完整title，详情路径映射至对应工单菜单 |
| 超时复选框被通用输入样式撑大 | 排除checkbox并统一尺寸；不影响radio和图片上传 |

## UI与交互

- 公共设计变量统一强调色、背景、辅助表面、状态色、圆角、焦点和轻阴影；清理重复表面覆盖与重复推荐原因样式。
- 登录保持校园构图，减轻阴影、缩短进入动画；全站只保留一次路由入场，避免页面再执行重复上浮。
- 首页、工单、步骤表单、维修/返工/预约、沟通与通知共享样式；提高辅助文字、时间线和状态标签可读性。
- 桌面时间线限制高度并可滚动；窄窗保留纵向真实事件顺序，避免两列拥挤或挤在详情前面。
- Dashboard降低信息密度和装饰，保留数据说明；数值更新从当前值过渡，动画约260ms。
- 推荐卡显示排名、四维评分和可展开的完整依据，首选展开，其他卡片收起；评分/权重不变。
- Dashboard与地图未选择标记时使用完整地图区域，点击后显示详情；窄窗自动纵向排列。
- 保留prefers-reduced-motion、键盘焦点、通知Escape关闭及响应式聊天输入；通知面板和Dialog高度受视口约束。

## 性能、安全与兼容性

学生首页汇总由5次档案查询+5次COUNT变为1次档案查询+1次聚合；维修员汇总为档案、聚合、今日派单共3次查询。Dashboard概览由6次订单COUNT+1次维修时长查询变为1次订单聚合+1次维修时长查询。汇总使用只读事务，维持一致读取。没有进行负载基准，不声称具体耗时提升。

保留BCrypt、JWT撤销/过期/角色校验、订单行锁、版本校验、维修轮次与派单历史、当前维修员聊天隔离、私有图片重编码和Validation。通知仍由AFTER_COMMIT监听器跨Bean调用REQUIRES_NEW写入；唯一幂等键基于动作、订单、轮次、事件ID、接收人。业务服务未直接写notification。两库的唯一索引均存在，隔离库47条带键通知对应47个不同键。

本轮未新增迁移，不重跑展示库迁移或写入测试工单。Git交付排除.runtime、真实.env、上传目录、日志、node_modules、target、dist；检查待提交文件未发现本机实际数据库密码/JWT密钥、私钥或GitHub令牌。

## 当前限制

- 未使用Computer Use、GUI或浏览器自动化。SSR、类型构建和真实HTTP不能证明实际浏览器布局、动画与控制台已人工验收，答辩前仍需按defense-guide.md手动检查。
- 校园地图仍为示例静态坐标；沟通/通知手动刷新，消息100条、通知50条；未绑定图片无自动清理。
- AFTER_COMMIT通知无持久重试，进程在业务提交后、通知落库前退出或通知写入失败时可能漏通知；不回滚已提交业务。

本轮完成后冻结功能，仅保留答辩前人工验收与真实校园资料准备。
