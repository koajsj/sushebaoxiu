# 毕业答辩演示指南

## 展示准备

启动README中的本机MySQL、后端和前端。先检查/api/health为UP。准备一张小于5MiB的PNG/JPEG现场照片，示例楼栋与人员静态坐标由dev-dispatch.sql提供并明确标注。若展示真实学校，先替换为真实WGS84坐标。

在浏览器两个独立配置或无痕窗口登录学生与管理员/维修人员。项目同源localStorage会同步账号，普通同一配置的新标签无法可靠保持三个不同账号；也可以在同一窗口依次退出切换。不要在展示库运行自动验收脚本，它们使用独立18085服务。

## 连续演示路线（约8～10分钟）

| 步骤 | 账号与入口 | 展示重点 |
| --- | --- | --- |
| 1 | admin001 → /admin/dashboard | 指标口径、真实数据、趋势与任务分布；没有工单时正常展示零值 |
| 2 | student001 → /student/orders/new | 五步选择故障、描述、地点、照片、确认；现场照片预览与提交反馈 |
| 3 | 学生详情 → 时间线及通知 | WAIT_AUDIT、本人订单归属和提交成功通知 |
| 4 | admin001 → /admin 工单详情 | 审核通过进入WAIT_ASSIGN，通知学生 |
| 5 | /admin/dispatch?orderId=实际订单ID | 候选分项、40/30/20/10权重、原因、管理员确认；10分钟内操作 |
| 6 | /admin/map | 选择本单标记，查看楼栋、地址、状态；说明人员为静态服务位置 |
| 7 | 被指定人员账号 → /worker/orders | 新任务通知，智能和人工派单均先明确接单，再开始维修 |
| 8 | 工单详情 → 维修沟通 | 学生与当前维修员文字交流，刷新读取；管理员仅查看 |
| 9 | 维修详情 | 开始维修、保存处理记录和结果照片，再完成进入WAIT_CONFIRM |
| 10 | student001 → 本单详情 | 确认FINISHED并评分，进入COMMENTED；每单一次评价 |
| 11 | admin001 → Dashboard刷新 | 创建与完成曲线、故障占比、完成率、人员评价变化 |

推荐名单是实时真实数据计算，结果可能随现有负载变化。记住实际选择人员对应账号；worker001、worker002、worker003都可以被推荐，不承诺固定第一名。人工派单入口保留在管理员订单详情。

若新订单不在派单队列，先检查已审核、尚未指定人员。若快照过期或负载已变，刷新推荐再确认。维修结果填写后必须先保存，完成按钮避免忽略未保存内容。聊天和通知手动刷新，不以无实时推送作为故障。

## 人工浏览器验收（交付前仍需执行）

本轮未使用Computer Use、GUI或浏览器自动化，以下是实际视觉验收清单，不能用SSR结果代替。

- 登录页桌面/手机布局、中文输入、回车提交、错误密码反馈；刷新保持身份、退出回登录。
- 320～430px窄屏无横向溢出；导航、通知关闭按钮、点击外部与Escape正常；Tab焦点清晰。
- 报修步骤焦点随标题更新，选择卡片反馈、上传预览、返回修改及最终提交反馈正常。
- 详情时间线只展示真实事件，多轮维修可折叠；长标题/长文字自动换行；结果图片比例正常。
- 智能派单分数动画、完整解释展开、重复点击禁用；地图缩放、拖动、重叠点选择正常。
- Dashboard零数据、少量数据与多名维修员布局；加载动画克制；减少动态效果设置有效。
- 聊天加载、空状态、错误重试、消息气泡、发送期间禁止刷新；通知已读后数量更新。
- 打开浏览器开发者工具确认没有未处理异常、资源404或明显控制台错误。

## 论文与答辩表达

[architecture.md](architecture.md)提供系统架构、功能结构、ER和流程四类图，以及评分规则和创新点说明。重点讲清角色与订单级权限、事务和行锁、可解释推荐快照、当前负载与累计完成量区别、统计时间口径。避免把规则评分称为AI，或把示例静态位置称为GPS实时定位。
