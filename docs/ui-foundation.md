# 前端设计系统与视觉资产

截至2026-10-01，Design System、Dashboard、派单、学生端、维修端、订单详情、聊天和通知均已迁移。下面保留UI-1阶段的基础设计说明；其中“后续迁移”是当时的阶段边界，当前状态见文末。

本轮建立公共视觉基础，仅将登录页和管理员 Dashboard 欢迎区接入校园资产。保留路由、角色权限、API、统计口径及所有表单和业务操作；不整体重写其他页面。

## 设计语言与文件职责

- `frontend/src/assets/design-system.css`：唯一的公共令牌、排版与状态色规范。浅蓝灰画布、白色内容面、校园蓝主色；成功、警告、错误使用独立语义色。Apple 风格仅为视觉参考，控件继续使用现有 Element Plus。
- `frontend/src/assets/component-system.css`：原生控件与 Element Plus 的公共组件样式。只引用 Design Token，统一按钮、表单、浮层、分页和上传的尺寸、布局及交互状态；业务页面只保留场景布局。
- `frontend/src/assets/main.css`：基础排版、品牌标识、登录构图、三角色共用 Layout 和 Dashboard 欢迎区。登录和 Layout 的旧重复覆盖已从 `experience.css` 移除。
- `frontend/src/assets/experience.css`：现有业务页面的迁移样式，继续保留；后续按页面迁移，不增加第二套全局令牌。
- `repair.css`、`dispatch-map.css`、`phase5.css`：各业务区域的现有结构规则；本轮保留。
- `StudentLayout`、`WorkerLayout`、`AdminLayout` 继续复用 `LayoutShell`，导航、折叠、通知、改密、退出及权限条件均保持原样。

公共导入顺序：页面结构样式 → `design-system.css` → `experience.css` → `component-system.css`。角色专属页面样式随路由加载；Element Plus 的控件覆盖使用更明确的选择器，避免懒加载库样式重新覆盖控件规范。后续共用控件回到组件样式修改，避免重复覆盖。

## 公共规范

| 范围 | 规范 |
| --- | --- |
| 颜色 | `--canvas`、`--surface`、`--ink`、`--muted`、`--accent`；状态使用 `--success`、`--warning`、`--danger` 与对应浅色背景 |
| 排版 | 系统字体，不下载字体；标题、模块标题、正文、辅助文字和数字分别使用 `--text-page`、`--text-section`、`--text-body`、`--text-support`、`--text-number` |
| 间距 | `--space-1` 至 `--space-8`，公共页面和面板使用 `--page-padding`、`--surface-padding` |
| 外壳 | 页面上限 1280px，侧栏 236px，折叠 96px；740px 以下横向导航可滚动，不删除导航入口 |
| 控件 | 按钮、输入、选择、Dialog/Drawer、卡片、表格、Tag/Badge、空状态及 Loading 使用已有库并映射共享令牌 |
| 圆角与阴影 | 三档圆角；内容面轻阴影，浮层单独使用 `--overlay-shadow`，不使用全站玻璃效果 |
| 动画 | 按压/悬停 120ms、一般反馈 180ms、初次进入 220ms；仅透明度与轻位移，不循环播放品牌图片动画 |
| 可访问性 | 保留跳转主内容链接、输入标签、键盘焦点；`prefers-reduced-motion` 关闭明显运动 |

## 校园视觉资产

原始素材由用户提供。参考 Dashboard 图片只用于观察构图、留白和层级，未导入到页面，也未复制其文字、数字、天气或业务模块。

| 资产 | 使用位置 | 图片文件 |
| --- | --- | --- |
| 智慧校园入口 | 登录 Hero | `entrance-1440.jpg` / `entrance-768.jpg` |
| 现代校园倒影池 | Dashboard 欢迎 Banner | `courtyard-1440.jpg` / `courtyard-768.jpg` |

四个文件位于 `frontend/src/assets/campus/`。使用 macOS 已有 `sips` 将原 PNG 等比例转换为 JPEG（质量 78），未修改原始下载文件；宽图约 390 KiB，窄图约 138 KiB。Vite 输出带哈希文件名，浏览器按窗口宽度选取一个尺寸，不把图片内联到 JavaScript。

共用 `CampusHero.vue`：

```vue
<CampusHero label="校园服务介绍" variant="login" asset="entrance">
  <!-- 保留当前页面的标题和介绍，不放业务按钮遮挡登录操作 -->
</CampusHero>

<CampusHero label="校园维修中心欢迎区域" asset="courtyard">
  <!-- 欢迎内容；统计图表和导出入口位于 Hero 外部 -->
</CampusHero>
```

- `picture` 在 740px 以下选择窄图，图片使用 `object-fit: cover`，不拉伸；登录裁剪位置为 `58% 52%`，Banner 为 `58% 63%`，保留更多建筑及庭院。明确宽高与容器高度，减少布局跳动。
- 深色渐变仅用于图片遮罩，文字保持白色及浅色辅助文字；桌面 Banner 文案限制在左侧 75%，窄屏使用全区域较强遮罩。最亮白色底图叠加文字区域最弱遮罩时，辅助文字的计算对比度约 4.90:1。
- 登录图片优先加载；Dashboard 图片可延迟加载。图片失败退回深蓝内容面，标题保持可读。
- 图片是校园品牌氛围素材，不代表真实楼栋、地图位置或维修现场；不得替代订单私有图片权限组件 `ProtectedImage`。
- 不在侧栏、每张卡片或每个空状态重复投放图片。其他欢迎/空状态暂不迁移，后续确有需要再复用。

## 后续迁移边界

学生、维修人员、工单详情、派单、聊天、通知等页面本轮只继承公共令牌和外壳，不改变内容顺序和操作条件。下一批先迁移一个页面并检查桌面/窄窗口，再沿用公共规则迁移后续页面。

构建与 Vue SSR 可以验证类型、路由和内容结构，不能代替实际浏览器对裁剪、视觉比例、动画、窄屏溢出与控制台的验收。本项目禁止 GUI 自动化，本轮不把上述浏览器项目宣称为已验收。

## 当前全站实现

| 区域 | 公共基础与当前实现 |
| --- | --- |
| 外壳与登录 | `LayoutShell`、`CampusHero`，三角色共享导航、账户操作和输入规范 |
| Dashboard / 派单 | 原统计API、本地SVG图表、推荐卡、四维评分、确认弹窗；数据来源及缺失值清楚标注 |
| 学生端 | `student-experience.css`：当前维修、状态卡片、五步报修和提交摘要 |
| 维修端 | `worker-experience.css`：行动型任务概览、任务卡片及返工提示 |
| 订单 / 聊天 / 通知 | `collaboration-experience.css`统一生命周期、按轮折叠、工单气泡、消息中心；学生端旧重复覆盖已删除 |
| 基础地图与管理表单 | 图层及图例共享`--map-*`令牌，辅助字号/输入/反馈复用全局规范 |

公共状态由`OrderStatusTag`和后端业务阶段展示，不由页面猜测。旧的学生/维修员专用详情Header、维修历史组件已由`components/lifecycle/`替代；只清理确认无引用的旧组件和样式。角色业务组件保留，避免强行合并相似流程。

动画沿用120/180/220ms规范；列表刷新不重播聊天整屏动画，数字变化支持减少动态效果。上传区包含加载状态播报，禁用时不显示可操作悬停反馈。长标题、模块头和工单信息允许换行，窄窗导航保留滚动入口。

实际像素布局、图片裁剪、动画观感和浏览器控制台仍需人工验收。当前证据及截图采集入口见[产品验收](product-acceptance.md)，不得将构建或SSR结果写成视觉验收通过。

## 组件体系精修（2026-10-02）

- 原生按钮：`primary-button`、`secondary-button`、`ghost-button`、`danger-button`、`text-button`；轻量危险操作使用 `danger-action`。已有按钮类与事件保持兼容，不包裹新的万能组件。
- 控件常规高度 42px、小型 36px、登录输入与主按钮 50px。输入、选择、日期与文本域共用焦点圈；校验失败使用错误色，禁用与加载保留可辨识反馈。原生字段选择器排除 Element Plus 内部输入，避免重复边框和内边距。
- Dialog 限制视口宽高，内容独立滚动、页脚与正文分隔；Drawer 按打开方向设置圆角。浮层、下拉项、表格与 Tag 使用相同语义令牌。未使用的库控件只有基础样式覆盖，没有新增页面或业务入口。
- 筛选区允许字段按剩余宽度换行；分页、确认区和操作区统一间距。单选选项和复选确认保留行内布局，不套用普通字段的网格排版。
- `ImageUpload` 保留单图选择、PNG/JPEG 与 5MB 校验、原上传请求和 `ProtectedImage` 权限加载。预览与移除操作集中展示，上传使用不定进度提示；按组件自身宽度决定单双列，适应详情侧栏和学生宽表单。
- 删除登录、业务通用、管理表单和角色页面里重复的输入焦点、按钮、上传与分页样式；角色专属信息布局继续保留。
- 构建、类型与 SSR 检查能验证代码和渲染结构，无法证明 1366px/1920px 下的实际视觉、拖入图片的浏览器行为或动画观感；这些项目需要手动验收。

## 角色体验差异化（2026-10-02）

- 同一 Design System 下保留独立角色首页：学生为校园维修服务入口，维修员为任务执行工作台，管理员为校园维修运营中心。`roleExperience.ts` 仅集中导航及引导文案，不承接权限或业务判断。
- 管理员 `/admin` 默认展示既有 Dashboard；`/admin/orders` 保留工单管理，`/admin/dashboard` 保留数据与报表入口。认证首页路径、三角色守卫与统计接口均不变。
- 学生导航强调「我要报修」「我的工单」；维修员增加既有筛选入口「已完成任务」，维修记录仍在任务详情中；通知菜单打开顶部同一个面板，不创建重复请求实例。账号安全复用原修改密码页，没有新增个人资料页或独立报表页。
- 维修员今日数字仍是今日派单，累计完成没有改写成今日完成；在途任务明确含维修、待验收及待返工。首页仅分组最近四份任务，空态不宣称全部任务为空，超时筛选入口始终可达。
- 列表、详情、聊天、通知按角色说明当前任务和下一步，危险动作说明拒单、驳回与收回的影响。原请求、并发防护、权限条件和状态流转保留。
- 导航与工具区窄窗可换行，减少动态效果沿用原规范。构建及 SSR 只证明代码和渲染结构；浏览器交互、视觉比例与动画仍需人工验收。
