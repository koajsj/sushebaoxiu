## 1. 审查发现及修复

| 发现 | 影响 | 处理 |
| --- | --- | --- |
| 聊天刷新与发送可同时进行 | 迟到的刷新结果覆盖新消息 | 请求互斥、失效响应保护，发送后保留最新100条 |
| 订单列表筛选失败保留旧结果 | 用户把旧数据当成新筛选结果 | 失败清空列表/数量，保留重试；目录与订单独立加载 |
| 管理员所有详情都查询维修员 | 无关请求失败使订单详情不可见 | 仅未分配WAIT_ASSIGN查询，人员错误局部显示 |
| 饼图分母取另一接口的订单总数 | 同时新增工单时圆弧与比例不一致 | 使用类型统计自身总数计算圆弧及中心总数 |
| 时间线有FINISH即把完成确认画为已完成 | 混淆维修完成与学生确认 | 依据订单当前状态区分完成/当前/等待节点 |
| 启用维修员每人查两次账号 | 2N+1查询增长 | 改为档案与账号两次批量查询，继续排除禁用/错误角色 |
| 更新评价均分读取全部订单与评分 | 大量实体与长IN列表 | 数据库JOIN AVG聚合，保留行锁、隔离级别和两位HALF_UP |
| 聊天分页产生无用途总数查询 | 每次刷新多一次COUNT | 关闭该页COUNT，保持最新100条及已读范围 |
| 通知缺少关闭/键盘操作 | 难以退出浮层，窄屏可能溢出 | 关闭、点击外部、Escape和焦点返回，响应式宽度/高度 |
| 未使用Phase1页面及重复阶段脚本 | 交付范围和入口混淆 | 删除失效视图/封装/样式，合并核心HTTP入口 |
| SSR检查开启无用途HMR端口 | 并行检查出现端口冲突提示 | 测试环境关闭HMR；重新检查没有该提示 |

没有发现需要调整JWT、角色模型、状态机、推荐算法或地图逻辑的高置信度缺陷。未改变数据库表、API契约或业务流程。

## 3. 性能与安全

查询减少为源码可确认的变化，没有做大规模性能基准，也不声称具体响应时间提升。人员候选固定两次批量查询；评价不再将全量实体载入Java；聊天少一次COUNT；已完成/非待派单详情不请求候选。保留已有路由懒加载、轻量SVG图表/地图及图片异步解码；Blob授权请求仍按现有机制获取，不声称图片网络请求已按可见区域延迟。

核查并保留BCrypt、HS256签名/issuer/过期校验、数据库当前角色与token_version撤销、路径级角色权限和订单归属。图片按真实格式重编码、随机文件名、限制大小/像素、路径及归属检查；前端使用授权Blob，消息以文本插值渲染，无v-html。API使用Validation与统一异常，客户端不接收原始堆栈。服务端参数化SQL与既有分页限制保留。

登录、角色拒绝、聊天归属、通知归属、退出后的旧令牌拒绝已做真实HTTP验证。图片上传/绑定/学生读取维修结果图片已验证；未把源码审查等同于全面渗透测试。
