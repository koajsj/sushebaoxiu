日期：2026-10-01。本页描述本轮改动；阶段性验证文档保留为当时快照。所有写入验证仅在 `campus_repair_final_check_20260930` 隔离库执行，展示库未迁移或写入。

## 修复与兼容

- 待开工新增按优先级的时限；已确认预约可调整时限。SLA仍不改变主状态，订单事件记录超时，收回或重派后旧时限清除。
- 服务器派生 `WAIT_DISPATCH`、`WAIT_ACCEPT`、`WAIT_START` 阶段供列表筛选、标签和操作使用；原状态值、历史派单和维修记录保留。
- 管理员可以收回待接单、待开工任务；维修中必须明确确认。收回与维修员操作共用工单行锁，关闭旧派单轮次、失效预约并撤销原维修员对当前工单、聊天和绑定图片的访问。待验收走原返工流程。
- 创建报修和保存维修记录要求 UUID 请求键。同键同载荷重试返回原结果或成功；不同载荷冲突。维修记录的新键允许相同文字。
- 推荐 GET 只读，POST 显式生成或刷新快照；确认派单仍复核当前工单和候选条件。
- 通知在主事务提交后投递到有界后台队列，独立事务与唯一键保障写入隔离和去重。队列拒绝或落库失败记录事件ID、键、业务ID与用户ID。**没有持久补偿**，业务成功后仍可能漏通知。
- 通知支持分页、未读筛选和按客户端已见最大ID全部已读；聊天支持前后游标及可见页面低频增量刷新。无负责人时学生与管理员仍可读历史但不能发送。
- 管理员可维护学生、维修员、楼栋坐标和故障类型；最后一个启用管理员不能停用，维修员在途任务未处理前不能停用。本人可校验旧密码修改密码，旧JWT随即失效。
- 登录失败限流为单进程内存方案；图片上传每张原有限制外另有每人10张未绑定额度，每日清理超过24小时且确认无引用的未绑定图片。上传事务回滚时删除刚写出的文件。

## 验证边界

Java 17 Maven打包、前端类型检查/生产构建、现有5类相关单元测试、前端会话/SSR定向检查，以及隔离库真实HTTP的创建重试、推荐只读、收回/接单竞争、重派后权限、待开工期限、维修记录重试、超过50条通知和100条聊天历史、管理员建档、改密和最后管理员保护均通过。隔离库中临时移开通知表模拟写入失败时，创建接口仍成功、订单已提交，日志记录了两个失败通知的事件ID和幂等键；表已恢复。另以临时数据库触发器强制收回事务在发布事件后失败，接口按数据库故障返回503，订单、派单历史、事件和对应通知均未提交；触发器已删除。前端真实HTTP核心闭环检查15项通过。
